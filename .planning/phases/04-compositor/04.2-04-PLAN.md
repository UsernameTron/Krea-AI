    ```javascript
    /**
     * compositePost — Phase 04.2 rewrite.
     * 3-layer pipeline: scene PNG + chrome PNG + text overlay.
     * D-NEW-01: Chrome is a static PNG asset, not programmatic.
     * D-NEW-02: Text overlay is the only dynamic rendering.
     * REQ-X-052b: Byte-identical output given identical inputs.
     */

    import sharp from 'sharp';
    import { existsSync, readFileSync } from 'node:fs';
    import { join } from 'node:path';
    import { fileURLToPath } from 'node:url';
    import { renderTextOverlay } from './render-text-overlay.js';
    import { VARIANT_SLOTS } from './constants.js';

    const __dirname = fileURLToPath(new URL('.', import.meta.url));
    const CHROME_DIR = join(__dirname, 'chrome-assets');

    // Valid variants per D-NEW-05
    const VALID_VARIANTS = new Set(['A', 'B', 'C', 'D']);
    const FALLBACK_VARIANT = 'B';

    // Output dimensions (REQ-X-060: 1920x1080 16:9)
    const OUTPUT_WIDTH = 1920;
    const OUTPUT_HEIGHT = 1080;

    /**
     * Resolve archetype scene_template to variant letter.
     * Fallback to B (executive strategy office) per D-NEW-05.
     */
    function resolveVariant(sceneTemplate) {
      const v = String(sceneTemplate ?? '').toUpperCase();
      return VALID_VARIANTS.has(v) ? v : FALLBACK_VARIANT;
    }

    /**
     * Composite a Post Brief v2 into a 1920x1080 PNG.
     *
     * @param {object} brief - Post Brief v2 (must have image_output.scene_png and image_seed.scene_template)
     * @returns {Promise<Buffer>} PNG buffer, 1920x1080, byte-identical for identical inputs
     */
    export async function compositePost(brief) {
      // --- Input validation ---
      if (brief == null) throw new Error('Post Brief is required');

      const scenePngPath = brief?.image_output?.scene_png;
      if (!scenePngPath || typeof scenePngPath !== 'string') {
        throw new Error('Post Brief must include image_output.scene_png (string path to scene PNG)');
      }
      if (!existsSync(scenePngPath)) {
        throw new Error(`Scene PNG not found: ${scenePngPath}`);
      }

      // --- Resolve variant ---
      const variant = resolveVariant(brief?.image_seed?.scene_template);
      const chromePngPath = join(CHROME_DIR, `variant-${variant.toLowerCase()}.png`);
      if (!existsSync(chromePngPath)) {
        throw new Error(`Chrome PNG not found for variant ${variant}: ${chromePngPath}`);
      }

      const slots = VARIANT_SLOTS[variant];
      if (!slots) {
        throw new Error(`VARIANT_SLOTS missing entry for variant ${variant}`);
      }

      // --- Load scene PNG as buffer ---
      const sceneBuffer = await sharp(scenePngPath)
        .resize(OUTPUT_WIDTH, OUTPUT_HEIGHT, { fit: 'cover', position: 'centre' })
        .png()
        .toBuffer();

      // --- Load chrome PNG as buffer ---
      // Chrome is a 1920x1080 RGBA PNG with transparent scene zone.
      // CRITICAL: Load as PNG buffer, NOT as raw RGBA. This avoids the BGRA
      // channel swap bug documented in tasks/lessons.md.
      const chromeBuffer = readFileSync(chromePngPath);

      // --- Render text overlay as PNG buffer ---
      // renderTextOverlay returns a PNG buffer (not raw RGBA) positioned at slots coordinates.
      const textOverlayBuffer = renderTextOverlay(brief, slots);

      // --- Composite: scene (bottom) -> chrome (middle) -> text (top) ---
      // ALL layers use input: <PNG Buffer> -- no raw: { channels: 4 } blocks.
      // This is a hard constraint per the BGRA lesson and operator mandate.
      const result = await sharp({
        create: {
          width: OUTPUT_WIDTH,
          height: OUTPUT_HEIGHT,
          channels: 4,
          background: { r: 255, g: 255, b: 255, alpha: 1 },
        },
      })
        .composite([
          // Layer 1: Scene PNG (full-bleed, from Phase 5)
          { input: sceneBuffer, top: 0, left: 0 },
          // Layer 2: Chrome PNG (transparent scene zone, opaque chrome)
          { input: chromeBuffer, top: 0, left: 0 },
          // Layer 3: Text overlay (headline + body in variant slots)
          { input: textOverlayBuffer, top: 0, left: 0 },
        ])
        .png({
          compressionLevel: 9,
          adaptiveFiltering: false, // Fixed filter = deterministic byte stream (REQ-X-052b)
        })
        .toBuffer();

      return result;
    }
    ```

    **Key design choices:**
    - `compositePost(brief)` takes ONLY the Post Brief v2 -- no separate heroImagePath parameter. Scene path comes from `brief.image_output.scene_png` per D-NEW-06 C3.
    - Chrome PNG loaded via `readFileSync()` as a raw file buffer (which Sharp handles as PNG input). NOT processed through `sharp().toBuffer()` to avoid unnecessary decode/encode.
    - All `sharp.composite()` layers use `input: <PNG Buffer>` -- zero `raw: { channels: 4 }` blocks. This is the BGRA mitigation.
    - `resolveVariant()` uppercases and validates against the enum. Fallback to B per D-NEW-05.
    - Output PNG uses `compressionLevel: 9, adaptiveFiltering: false` for determinism per REQ-X-052b.

    Write tests in `mirror-post/test/compositor-composite-v2.js`. Tests will need mock scene and chrome PNG fixtures. Create minimal 1920x1080 test PNGs via sharp in the test setup (solid color rectangles are sufficient for shape/pipeline validation).

  <name>Task 2: Update renderTextOverlay() to accept VARIANT_SLOTS coordinates</name>
  <files>mirror-post/src/compositor/render-text-overlay.js</files>
  <action>
    **Update `renderTextOverlay()` signature and internals:**

    The function currently takes `(brief, zones)` where zones is the full zone-spec.json object. Under the rewrite, it receives `(brief, slots)` where slots is a single variant's VARIANT_SLOTS entry (e.g., `VARIANT_SLOTS.A` with `{ headline: {...}, body: {...} }`).

    **Changes required:**

    1. **Signature change:** `renderTextOverlay(brief, slots)` where `slots` is `{ headline: {x, y, width, height, fontSize, lineHeight, maxLines, fontWeight, color}, body: {...} }`.

    2. **Return type change:** Return a **1920x1080 PNG Buffer** instead of a raw RGBA buffer at a sub-canvas offset. The composite.js rewrite needs all layers as PNG buffers (no raw RGBA). Create a 1920x1080 canvas, draw text at the slot's absolute (x, y) coordinates, export as PNG buffer.

    3. **Replace hardcoded zone constants:** Remove the hardcoded `OVERLAY_WIDTH`, `OVERLAY_HEIGHT`, `OVERLAY_X`, `OVERLAY_Y`, `HEADLINE_X`, etc. Replace with values from the `slots` parameter:
       - Headline position: `slots.headline.x`, `slots.headline.y`
       - Headline dimensions: `slots.headline.width`, `slots.headline.height`
       - Headline font: `slots.headline.fontSize`, `slots.headline.lineHeight`, `slots.headline.fontWeight`
       - Headline color: `slots.headline.color` (override the `COLORS.textWhite` default)
       - Body: same pattern using `slots.body.*`

    4. **Gradient mask:** The current gradient covers the entire 730x824 overlay. Under the new architecture, the gradient is either:
       - (a) Baked into the chrome PNG (operator decision), OR
       - (b) Drawn by renderTextOverlay behind the text.
       For now, KEEP the gradient rendering but make it span the text zone implied by the slots. Draw a linear gradient from `slots.headline.x - 20` to `slots.body.x + slots.body.width + 100`, with the same opacity stops. This ensures text readability over the scene PNG regardless of whether the chrome PNG includes a gradient. If the operator's chrome PNG already has a gradient, the double-gradient will be slightly darker but not broken -- acceptable for v1. The operator can disable the code-side gradient later.

    5. **Hashtag rendering:** The current code draws hashtags below the body. Under VARIANT_SLOTS, there's no explicit hashtag slot (only headline and body per D-NEW-03). Options:
       - Drop hashtag rendering from the compositor (hashtags are secondary to headline/body)
       - Add hashtags to the bottom of the body zone if space permits
       Choose: render hashtags at `slots.body.y + slots.body.height + 8` (below body zone) if the slot coordinates allow it (y + height < 1080). Cap at one line. Use `slots.body.x` for left alignment, gold color.

    6. **Export `buildStyledSegments`:** Add `export` keyword to the `buildStyledSegments` function declaration (per 04.2-02 barrel requirement).

    7. **Canvas output format:** `canvas.toBuffer('image/png')` instead of `canvas.toBuffer('raw')`. This produces a PNG buffer that sharp.composite() can consume without `raw: { channels: 4 }` -- the BGRA mitigation.

    **Test updates:** Existing render-text-overlay tests may need updating for the new signature. If `mirror-post/test/compositor-text-tweet.js` covered text overlay, those tests move to `mirror-post/test/compositor-composite-v2.js` (from Task 1) or a new `mirror-post/test/text-overlay-v2.js`.
