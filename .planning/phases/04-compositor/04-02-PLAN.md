**`export function renderTextOverlay(brief, zones)`** → `{ buffer: Buffer, x: number, y: number }`

Implementation steps:

1. **Create canvas** at text_overlay_zone dimensions: width=730, height=824.

2. **Draw gradient mask.** Use Canvas 2D `createLinearGradient(0, 0, 730, 0)` with zone-spec gradient stops:
   - offset 0.0: `rgba(0,0,0,0.82)` (82% black at left edge)
   - offset 0.7: `rgba(0,0,0,0.45)` (45% at 70% across)
   - offset 1.0: `rgba(0,0,0,0)` (transparent at right edge)
   Fill the entire 730x824 canvas with this gradient.

3. **Render headline** in sub_zones.headline area (x=40, y=200 relative to overlay origin, so local y = 200-124 = 76; width=650, height=120).
   - Parse headline text: split `brief.post.headline.text` into words
   - For each word, check if it's in `brief.post.headline.highlight_words` (case-insensitive match)
   - If highlighted: set fillStyle to `brief.post.headline.highlight_color` (default `#FFD700`)
   - If not highlighted: set fillStyle to `COLORS.textWhite` (#FFFFFF)
   - Font: Inter Bold at FONTS.headlineSize (36px)
   - Apply text shadow per D-11: `ctx.shadowColor = 'rgba(0,0,0,0.6)'; ctx.shadowBlur = 8; ctx.shadowOffsetX = 2; ctx.shadowOffsetY = 2;`
   - Word-wrap: measure each word with `ctx.measureText(word + ' ')`, accumulate x. When x + wordWidth > 650, move to next line (lineHeight = 44px for 36px font)
   - Truncation safety: if headline text > 60 chars, truncate to 57 chars + "..." before rendering (per D-12)

4. **Render body text** in sub_zones.body area (x=40, y=340 relative to overlay origin, so local y = 340-124 = 216; width=650, height=400).
   - **Inline formatting tokenizer (per D-10):** Split body text into segments. For each segment, determine if it matches any entry in `brief.post.body.bold_phrases` or `brief.post.body.italic_phrases`:
     - Build a list of styled segments: `[{ text, style: 'normal'|'bold'|'italic' }]`
     - Algorithm: scan body text left-to-right. For each bold_phrase, find its position in text and mark as bold. For each italic_phrase, find and mark as italic. Remaining text is normal.
     - Simple approach: sort all phrase positions, iterate through text creating segments between matches.
   - For each segment, set ctx.font appropriately:
     - normal: `${bodyFontSize}px Inter` (Inter Regular 18px)
     - bold: `bold ${bodyFontSize}px Inter` (Inter Bold 18px)
     - italic: `italic ${bodyFontSize}px Inter` (Inter Regular Italic 18px — canvas will synthesize italic from Regular if no italic TTF is registered)
   - fillStyle: COLORS.textWhite for all body text
   - Apply same text shadow as headline
   - Word-wrap with per-word measureText across the 650px width, lineHeight = 26px for 18px font
   - **Overflow handling (per D-12):** If total rendered height exceeds 400px (body zone height), try reducing bodyFontSize by 2pt (to 16px). If still overflowing at 16px, try 14px (minimum). If still overflowing, truncate remaining text with "..." at zone boundary.

5. **Render hashtags** in sub_zones.hashtags area (x=40, y=760 relative to overlay origin, so local y = 760-124 = 636; width=650, height=40).
   - Join `brief.post.hashtags` with " " separator
   - Font: Inter Regular at FONTS.hashtagSize (14px)
   - fillStyle: COLORS.highlightGold (#FFD700) — hashtags in gold to match highlight treatment
   - Single line, truncate with "..." if exceeds 650px width

6. **Return** `{ buffer: canvas.toBuffer('raw'), x: 0, y: 124 }` (position from zone-spec text_overlay_zone).

**Purpose:** The Task 1 + Task 2 determinism tests prove "two compositor calls in the same process match each other." That is necessary but NOT sufficient for REQ-X-052. A future sharp/canvas/font upgrade could shift every pixel by 1 unit — both within-run calls would still match, but the output would have silently drifted from the approved baseline. This task adds a cross-run anchor: a committed golden PNG that pins the current output as "approved." Any future drift from that baseline fails the test.

**Step 1: Generate and commit the golden PNG.**

Run this script once (from `mirror-post/` directory) to produce the golden fixture:

```javascript
// scripts/generate-golden.mjs (one-shot, can be deleted after — or kept for regeneration)
import { compositePost } from '../src/compositor/index.js';
import { readFileSync, writeFileSync, mkdirSync } from 'node:fs';
import sharp from 'sharp';

const brief = JSON.parse(readFileSync('test/fixtures/expected-briefs/brent-vellum.json', 'utf-8'));

// Fixed solid-color hero — RGB (100, 150, 200), 1920x1080. Seed is the color tuple itself; any drift in the hero path would invalidate the golden.
const heroBuffer = await sharp({
  create: { width: 1920, height: 1080, channels: 3, background: { r: 100, g: 150, b: 200 } }
}).png().toBuffer();
writeFileSync('/tmp/golden-hero.png', heroBuffer);

const output = await compositePost(brief, '/tmp/golden-hero.png');

mkdirSync('test/fixtures/golden-outputs', { recursive: true });
writeFileSync('test/fixtures/golden-outputs/brent-vellum-golden.png', output);
console.log('Golden written:', output.length, 'bytes');
```

Run: `cd mirror-post && node scripts/generate-golden.mjs`

Then `git add mirror-post/test/fixtures/golden-outputs/brent-vellum-golden.png` and commit the binary. This golden PNG becomes the approved baseline — any future compositor change that shifts pixels must either match this golden or the developer must explicitly regenerate it (a deliberate baseline update, reviewed in PR).

**Step 2: Create `test/compositor-golden.js`** — the cross-run determinism test.

Follow the existing test harness pattern (pass/fail counters, process.exit(1) on failure):

```javascript
import { compositePost } from '../src/compositor/index.js';
import { readFileSync } from 'node:fs';
import sharp from 'sharp';

let passed = 0, failed = 0;

// Load brief and golden
const brief = JSON.parse(readFileSync('test/fixtures/expected-briefs/brent-vellum.json', 'utf-8'));
const golden = readFileSync('test/fixtures/golden-outputs/brent-vellum-golden.png');

// G1: golden PNG is a valid PNG
const pngMagic = Buffer.from([0x89, 0x50, 0x4E, 0x47]);
if (golden.subarray(0, 4).equals(pngMagic)) { passed++; } else { failed++; console.error('G1 FAIL: golden not a PNG'); }

// G2: golden metadata is 1920x1080
const meta = await sharp(golden).metadata();
if (meta.width === 1920 && meta.height === 1080) { passed++; } else { failed++; console.error('G2 FAIL: golden dims', meta.width, meta.height); }

// G3: fresh compositor output byte-matches golden (using identical inputs)
const heroBuffer = await sharp({
  create: { width: 1920, height: 1080, channels: 3, background: { r: 100, g: 150, b: 200 } }
}).png().toBuffer();
const { writeFileSync } = await import('node:fs');
writeFileSync('/tmp/golden-hero-test.png', heroBuffer);
const output = await compositePost(brief, '/tmp/golden-hero-test.png');

if (Buffer.compare(output, golden) === 0) {
  passed++;
} else {
  failed++;
  console.error('G3 FAIL: Compositor output has drifted from approved baseline.');
  console.error('  Golden size:', golden.length, 'bytes');
  console.error('  Output size:', output.length, 'bytes');
  console.error('  This is NOT a within-run flake — the compositor has changed since the golden was committed.');
  console.error('  If this drift is intentional (e.g. sharp upgrade, layout fix), regenerate golden via scripts/generate-golden.mjs and commit.');
}

console.log(`\nGolden tests: ${passed} passed, ${failed} failed`);
process.exit(failed > 0 ? 1 : 0);
```
