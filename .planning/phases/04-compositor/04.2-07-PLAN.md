  <name>Task 1: Author FLUX scene workflow doc</name>
  <files>mirror-post/docs/flux-scene-workflow.md</files>
  <action>
    Create `mirror-post/docs/flux-scene-workflow.md` documenting:

    **Purpose.** Path C compositor layers a FLUX-generated SCENE PNG into the `HERO_ZONE` of a shared LinkedIn HTML template. FLUX only generates the scene (background + subject visual context). All UI, chrome, and text come from Puppeteer rendering `linkedin-post.html`.

    **Hard rule — no text in FLUX.** FLUX garbles embedded text. Prompts MUST NOT ask FLUX to render captions, nameplates, UI buttons, icons, hashtags, or any written glyphs. If a scene conceptually needs a "sign" or "screen," describe it as blurred, abstract, or out-of-focus.

    **Variants.** Four variants (A/B/C/D) share the same HTML chrome. They differ only in the scene PNG composited at HERO_ZONE. Each variant has a dedicated prompt file under `src/compositor/scene-prompts/variant-{letter}.txt` and a pool of generated PNGs under `src/compositor/scene-assets/{letter}/scene-*.png`.

    **Selection.** The compositor selects one scene from the pool via `sub_n = SHA-256(character.name + post.headline.text) mod pool_size`, guaranteeing the same brief always picks the same scene (D-NEW-15).

    **Workflow.**
    1. Operator reviews the variant prompt file.
    2. Operator runs FLUX N times against the prompt (N = desired pool size, suggested 8).
    3. Operator curates — rejects any scene where FLUX accidentally produced text, faces with visible distortion, or broken perspective.
    4. Operator writes curated scenes to `scene-assets/{letter}/scene-001.png`, `scene-002.png`, etc., zero-padded sequential filenames.
    5. Operator commits the scene PNGs — they are part of the deterministic output contract.

    **Determinism stack recap (D-NEW-16).** Three legs: pinned Chromium (exact puppeteer version), bundled Inter TTFs via @font-face, PNG-buffer sharp composite. Replacing or regenerating any scene PNG invalidates golden fixtures — intentional.

    **Resolution.** Target resolution matches HERO_ZONE dimensions (see `src/compositor/templates/hero-zone.js`). Over-resolution is fine — the compositor resizes via sharp `fit: 'cover'`. Under-resolution causes blur; avoid.
  </action>
  <done>flux-scene-workflow.md documents purpose, hard rule, variants, selection, workflow, determinism, and resolution.</done>
