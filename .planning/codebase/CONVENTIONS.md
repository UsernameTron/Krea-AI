# Coding Conventions

> Generated by gsd-codebase-mapper (quality focus) on 2026-04-13

## Naming Patterns

**Files:**
- Snake_case module names: `config.py`, `pipeline.py`, `test_pipeline.py`
- Test files prefixed with `test_`: `test_config.py`, `test_metal.py`, `test_neural_engine.py`
- Optimizer modules live in `optimizers/` subpackage: `optimizers/metal.py`, `optimizers/thermal.py`, `optimizers/neural_engine.py`
- Utility modules live in `utils/` subpackage: `utils/benchmark.py`, `utils/monitor.py`, `utils/profiler.py`

**Classes:**
- PascalCase for all classes: `FluxKreaPipeline`, `FluxConfig`, `MetalOptimizer`, `ThermalManager`, `NeuralEngineOptimizer`, `FluxWebApp`
- Config dataclasses named with `Config` suffix: `ModelConfig`, `DeviceConfig`, `GenerationConfig`, `SafetyModeConfig`, `ThermalConfig`, `WebConfig`, `OutputConfig`
- Enums named with descriptive noun: `OptimizationLevel`, `ThermalState`, `ThermalMode`

**Functions and methods:**
- Snake_case: `get_config()`, `apply_mps_environment()`, `get_hf_token()`
- Private methods prefixed with single underscore: `_detect_device()`, `_configure_environment()`, `_cleanup_memory()`, `_load_at_level()`, `_apply_standard_optimizations()`
- No double-underscore name mangling in production code

**Variables and parameters:**
- Snake_case throughout: `mock_from_pretrained`, `progress_callback`, `num_inference_steps`
- Boolean flags named with verb prefix: `is_loaded`, `is_estimated`, `metal_available`
- Constants in SCREAMING_SNAKE_CASE: `ANE_MAX_MODEL_SIZE_BYTES`, `BYTES_PER_PARAM_BF16`, `FLUX_COMPONENT_PARAMS`

**Enum values:**
- SCREAMING_SNAKE_CASE for enum member names: `OptimizationLevel.NONE`, `OptimizationLevel.STANDARD`, `OptimizationLevel.MAXIMUM`
- Lowercase string values: `"none"`, `"standard"`, `"maximum"`, `"optimal"`, `"warm"`, `"hot"`, `"critical"`

## Code Style

**Formatting:**
- Tool: `ruff` (configured in `ruff.toml`)
- Line length: 120 characters maximum
- Target version: Python 3.10

**Linting:**
- Ruff rule sets active: `E` (pycodestyle errors), `F` (pyflakes), `W` (pycodestyle warnings)
- Ignored globally: `E501` (line too long — line-length rule takes precedence), `F401` (unused imports)
- Tests directory ignores: `E501`
- Excluded from linting: `.claude/`, `.claire/`

**Type checking:**
- Tool: `mypy`
- Python version target: 3.10
- `ignore_missing_imports = true` — external library stubs not required
- `warn_return_any = false` — return type inference not enforced
- Tests directory excluded from mypy: `exclude = ["tests/"]`
- Type annotations used throughout production code but not exhaustively

## Import Organization

**Order (observed pattern in `pipeline.py`, `config.py`, `app.py`):**
1. Standard library imports (`gc`, `logging`, `os`, `time`, `threading`, `contextlib`, `pathlib`, `typing`)
2. Third-party imports (`torch`, `diffusers`, `yaml`, `gradio`, `PIL`)
3. Local/project imports (from `config`, `pipeline`, `optimizers.*`, `utils.*`)

**Style:**
- Imports grouped with blank line between groups (no blank line enforced within groups)
- `from module import name` preferred over `import module` for specific symbols
- `from typing import Any, Callable, Optional` — explicit Optional, not `X | None` (Python 3.10 compat)
- Lazy imports inside function bodies for optional heavy dependencies (diffusers, coremltools, psutil): avoids import-time failures when optional packages absent

**Example from `pipeline.py`:**
```python
import gc
import logging
import os
import time
from contextlib import contextmanager
from pathlib import Path
from typing import Any, Callable, Optional

import torch
import torch.backends.mps

from config import (
    FluxConfig,
    OptimizationLevel,
    apply_mps_environment,
    get_config,
    get_hf_token,
)
```

**Path aliases:**
- None — all imports use project-relative module names; `sys.path.insert(0, ...)` used in `tests/conftest.py` to ensure project root is importable

## Docstrings

**Module-level docstrings:**
- Required on every module. Single line or multiline. Example from `pipeline.py`:
  ```python
  """
  Unified FLUX.1 Krea Pipeline.
  Replaces: flux_krea_official.py, flux_krea_m4_optimized.py, ...
  """
  ```

**Class docstrings:**
- Describe the class purpose and, for complex classes, enumerate key behaviors. Example:
  ```python
  class FluxKreaPipeline:
      """Unified FLUX.1 Krea pipeline with configurable optimization levels.

      Optimization levels:
          NONE:     Baseline diffusers FluxPipeline, no extras.
          STANDARD: MPS device + attention slicing + VAE tiling + CPU offload.
          MAXIMUM:  All of STANDARD + Metal kernel optimizations + thermal management.

      Fallback chain: MAXIMUM -> STANDARD -> NONE (with warnings).
      """
  ```

**Method/function docstrings:**
- Public methods document purpose, `Args:` block, and `Returns:` block using Google style.
- Private helper methods use single-line or short paragraph docstrings.
- Example from `generate()` in `pipeline.py`:
  ```python
  def generate(self, prompt: str, ...) -> ...:
      """Generate an image from a text prompt.

      Args:
          prompt: Text description of the image to generate.
          width: Image width (multiple of 64). Uses config default if None.
          ...

      Returns:
          PIL.Image.Image: The generated image.
      """
  ```

**Test file docstrings:**
- Module-level docstring explains patching strategy when non-obvious (see `test_app.py`, `test_main.py`)
- Class docstrings used sparingly, only for complex test groups (e.g., `TestLoadFallbackChain`)
- Individual test methods have no docstrings unless behavior is non-obvious; intent is expressed in method name

## Type Annotations

**Production code:**
- All public method signatures annotated with parameter types and return types
- `Optional[X]` used for nullable params (not `X | None`) for Python 3.10 compat
- `Any` used for the diffusers pipeline object (third-party type not stubs-available)
- Dataclass fields have type annotations via standard `@dataclass` pattern
- `# type: ignore[...]` comments used when yaml library lacks stubs (`yaml  # type: ignore[import-untyped]`)

**Test code:**
- No type annotations in tests (mypy excludes tests directory)

## Error Handling

**Strategy: explicit fallback chains, no silent swallowing in production paths.**

**Patterns observed:**

1. **Fallback with logging:** Used extensively in `pipeline.py` for optimization level downgrades:
   ```python
   except Exception as e:
       logger.warning("MAXIMUM optimization failed (%s), falling back to STANDARD", e)
       self._load_at_level(OptimizationLevel.STANDARD, progress_callback)
   ```

2. **Silent swallow for optional features:** Used when a feature is genuinely optional and absence is acceptable:
   ```python
   except Exception:
       pass  # CPU offload not available
   ```
   Always paired with a log at `debug` or `warning` level.

3. **Specific exception types preferred:** `RuntimeError` for hardware/device errors, `ImportError` for optional dependency absence, `ValueError` for validation failures.

4. **Validation via `ValueError`:** The `FluxConfig.validate()` method collects all errors into a list and raises a single `ValueError` with all issues concatenated — avoids multiple exception raises.

5. **No bare `except:`:** All except clauses specify a type or catch `Exception` explicitly.

6. **MPS watermark error special-casing:**
   ```python
   except RuntimeError as e:
       if "watermark" in str(e).lower():
           logger.debug("MPS cache clear skipped (watermark ratio): %s", e)
       else:
           logger.warning("MPS cache clear failed: %s", e)
   ```

## Logging

**Framework:** Python standard `logging` module.

**Logger per module:**
```python
logger = logging.getLogger(__name__)
```
Every module that logs declares its own module-level logger. No root logger manipulation.

**Log level conventions:**
- `logger.info(...)` — Normal operational events (pipeline loaded, generation complete, optimizations applied)
- `logger.warning(...)` — Degraded but functional state (fallback triggered, MPS cache error, optional feature unavailable)
- `logger.debug(...)` — Expected suppressed events in normal operation (watermark ratio skips)
- No `logger.error()` or `logger.critical()` observed — errors propagate as exceptions instead

**Format string style:**
- `%`-style lazy formatting, not f-strings: `logger.info("Loading pipeline: device=%s, level=%s", self.device, level.value)`
- This is idiomatic with Python's logging module to avoid string formatting when log level is disabled

## Configuration Pattern

**Priority chain (documented in `config.py` docstring and enforced in `get_config()`):**
```
CLI overrides > FLUX_ env vars > config.yaml > dataclass defaults
```

**Dataclass composition:** Each concern is its own `@dataclass` (`ModelConfig`, `DeviceConfig`, `GenerationConfig`, etc.) composed into the top-level `FluxConfig`. This keeps validation and defaults localized.

**Environment variables:** All use `FLUX_` prefix. Type conversion handled per-variable in `_apply_env_vars()`.

**HuggingFace token:** Always read from environment (`HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN`). Never hardcoded. Accessed via `get_hf_token()`.

## Function Design

**Public functions/methods:**
- Accept `Optional[X] = None` for optional parameters rather than sentinel values (except seed, where `-1` is used in the Gradio UI layer as a "no seed" indicator)
- Return tuples for multiple values: `generate()` returns `(image, metrics_dict)`
- Return `Path` objects for file paths, not strings

**Private methods:**
- Extract non-trivial implementation details: `_apply_standard_optimizations()`, `_apply_maximum_optimizations()`, `_cleanup_memory()` are private implementation details of `FluxKreaPipeline`
- Context managers decorated with `@contextmanager`: `_inference_context()`, `metal_kernel_context()`

**Module design:**
- No barrel `__init__.py` exports for production modules (each module imported directly)
- `optimizers/__init__.py` exposes `get_optimizer()` factory function as the public interface
