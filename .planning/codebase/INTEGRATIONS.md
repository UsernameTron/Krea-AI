# External Integrations

> Generated by gsd-codebase-mapper (tech focus) on 2026-04-13

## APIs & External Services

**Hugging Face Hub:**
- Purpose: Model weight download for `black-forest-labs/FLUX.1-Krea-dev` (12B parameter FLUX.1 flow-matching transformer)
- SDK: `huggingface-hub>=0.30.0`; accessed via `diffusers.FluxPipeline.from_pretrained()`
- Auth: `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN` environment variable (never hardcoded — enforced in `flux-krea/config.py` `get_hf_token()`)
- Access required: Model is gated; user must request access at `https://huggingface.co/black-forest-labs/FLUX.1-Krea-dev` and accept license
- Token permissions: Read access sufficient
- Error handling: `app.py` `_format_error()` provides specific user guidance for 401/403/gated errors

## Data Storage

**Databases:**
- None — no database of any kind.

**Model Weight Cache:**
- Type: Local filesystem
- Location: `~/.cache/huggingface/hub/` (standard Hugging Face Hub cache)
- Populated: On first `FluxPipeline.from_pretrained()` call
- Format: `safetensors` (enforced via `use_safetensors=True`)
- Detection: `main.py` `cmd_info()` checks `~/.cache/huggingface/hub/models--black-forest-labs--FLUX.1-Krea-dev*` to report cache status

**Generated Image Output:**
- Type: Local filesystem
- Default location: `./outputs/` (relative to working directory at runtime)
- Configurable via: `FLUX_OUTPUT_DIRECTORY` env var or `output.directory` in `config.yaml`
- Filename pattern: `flux_{timestamp}_{prompt_slug}.png` (configurable via `output.filename_pattern`)
- Format: PNG via `PIL.Image.save()`

**Neural Engine CoreML Cache:**
- Type: Local filesystem
- Default location: `./neural_engine_cache/` (relative to working directory)
- Contents: `vae_decoder.mlpackage` — CoreML-converted VAE decoder (when `coremltools` is installed and conversion succeeds)
- Created by: `flux-krea/optimizers/neural_engine.py` `NeuralEngineOptimizer`
- Fallback: Pipeline continues on MPS if cache is absent or conversion fails

**File Storage:**
- Local filesystem only. No S3, GCS, or remote storage of any kind.

**Caching:**
- No Redis, Memcached, or in-process cache layer. Caching is limited to HF Hub's on-disk model cache and the optional CoreML `.mlpackage` cache.

## Authentication & Identity

**Auth Provider:**
- Hugging Face Hub token auth only (for model download)
- No user authentication, no sessions, no OAuth for the application itself
- Implementation: `get_hf_token()` in `flux-krea/config.py` reads `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN` from environment; passed implicitly to HF Hub client

## Hardware Accelerators (Platform Integrations)

**Apple Metal Performance Shaders (MPS):**
- Interface: `torch.backends.mps` — availability check and device placement
- Memory management: `torch.mps.empty_cache()`, `torch.mps.set_per_process_memory_fraction()`, `torch.mps.current_allocated_memory()`
- Environment tuning: `PYTORCH_MPS_HIGH_WATERMARK_RATIO`, `PYTORCH_MPS_LOW_WATERMARK_RATIO`, `PYTORCH_MPS_MEMORY_FRACTION`, `PYTORCH_MPS_ALLOCATOR_POLICY`, `PYTORCH_MPS_PREFER_FAST_ALLOC`
- Implementation: `flux-krea/optimizers/metal.py` `MetalOptimizer`; applied in `pipeline.py` `_apply_maximum_optimizations()`

**Apple Neural Engine (ANE) / CoreML:**
- Interface: `coremltools>=8.0` (optional dependency — lazy import in `flux-krea/optimizers/neural_engine.py`)
- Usage: `ct.convert()` traces VAE decoder via `torch.jit.trace()` and converts to `.mlpackage` targeting `ct.ComputeUnit.ALL` (CPU/GPU/ANE), `minimum_deployment_target=ct.target.macOS13`
- Realistic scope: Only the VAE decoder (~100M params) is convertible; T5-XXL text encoder (~11B params) and flow transformer (~12B params) exceed the ~4GB ANE model size limit
- Implementation: `flux-krea/optimizers/neural_engine.py` `NeuralEngineOptimizer`

## Monitoring & Observability

**System Temperature Monitoring:**
- Priority chain (implemented in `flux-krea/optimizers/thermal.py`):
  1. `sysctl -n machdep.xcpm.cpu_thermal_state` (no sudo, fastest)
  2. `psutil.sensors_temperatures()` (cross-platform)
  3. `sudo /usr/bin/powermetrics -n 1 -s thermal` (most accurate, requires sudo)
  4. Returns `None` if no real data available — no fake estimates
- Used by: `ThermalManager` background monitoring thread; adjusts `inference_steps_scale` during generation

**System Resource Monitoring:**
- `psutil` — RAM total/used percent, CPU core counts
- `torch.mps.current_allocated_memory()` — MPS VRAM allocated
- Exposed via: `pipeline.get_system_info()` and `utils/monitor.py` `get_system_info()`
- Displayed in: Gradio web UI debug panel (`app.py` `_get_system_info_text()`)

**Error Tracking:**
- None (no Sentry, Datadog, or similar external service)

**Logs:**
- Python `logging` module; all modules use `logging.getLogger(__name__)`
- Level: `INFO` by default; `DEBUG` with `--verbose` CLI flag
- Format: `%(asctime)s [%(levelname)s] %(name)s: %(message)s`
- Web UI: Rolling 50-entry in-memory `deque` (`_debug_log` in `app.py`) displayed in the Gradio debug accordion

## System Commands (External Process Calls)

The following OS-level commands are invoked via `subprocess.run()` by `ThermalManager`:

| Command | Purpose | sudo Required |
|---------|---------|---------------|
| `sysctl -n machdep.xcpm.cpu_thermal_state` | Read CPU thermal state (macOS) | No |
| `sudo /usr/bin/powermetrics -n 1 -s thermal` | Read CPU die temperature | Yes (rarely tried) |

All subprocess calls use `capture_output=True`, `timeout=2-5s`, and fail silently with `None` return — no hard dependency on these commands succeeding.

## Environment Configuration Summary

**Required:**
- `HF_TOKEN` (or `HUGGING_FACE_HUB_TOKEN`) — Hugging Face authentication token

**MPS Tuning (set automatically from config, can override via env):**
- `PYTORCH_MPS_HIGH_WATERMARK_RATIO` — default 0.8
- `PYTORCH_MPS_LOW_WATERMARK_RATIO` — default 0.6
- `PYTORCH_MPS_MEMORY_FRACTION` — default 0.85
- `PYTORCH_MPS_ALLOCATOR_POLICY` — default `expandable_segments`
- `PYTORCH_MPS_PREFER_FAST_ALLOC` — default `1`
- `PYTORCH_ENABLE_MPS_FALLBACK` — default `1`

**Generation Overrides (optional):**
- `FLUX_MODEL_ID` — model identifier (default: `black-forest-labs/FLUX.1-Krea-dev`)
- `FLUX_MODEL_DTYPE` — tensor dtype (default: `bfloat16`)
- `FLUX_DEVICE_PREFERRED` — compute device (default: `mps`)
- `FLUX_GENERATION_WIDTH`, `FLUX_GENERATION_HEIGHT` — image dimensions
- `FLUX_GENERATION_STEPS` — denoising steps
- `FLUX_GENERATION_GUIDANCE_SCALE` — CFG scale
- `FLUX_SAFETY_MODE` — `1`/`true`/`yes` enables safety mode
- `FLUX_THERMAL_MODE` — `maximum`, `balanced`, `efficient`, or `adaptive`
- `FLUX_WEB_HOST`, `FLUX_WEB_PORT` — Gradio server binding
- `FLUX_OUTPUT_DIRECTORY` — output image directory
- `FLUX_OPTIMIZATION_LEVEL` — `none`, `standard`, or `maximum`

**Secrets location:**
- `.env` file (gitignored, loaded by `launch.sh`); contents are never hardcoded in source
