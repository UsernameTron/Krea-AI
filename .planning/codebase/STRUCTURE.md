## Directory Purposes

**`optimizers/`:**
- Purpose: Hardware-specific optimization plugins, each independently optional
- Contains: Three optimizer classes + factory function
- Key files: `metal.py` (164 lines), `neural_engine.py` (549 lines — most complex), `thermal.py` (250 lines)
- Activation: Only instantiated by `pipeline.py` at MAXIMUM optimization level (lazy imports)

**`utils/`:**
- Purpose: Diagnostic, measurement, and benchmarking tools used by CLI subcommands only
- Contains: `run_benchmark()`, `get_system_info()`, `FluxProfiler`
- Key files: `profiler.py` (361 lines — most complex util), `benchmark.py` (71 lines), `monitor.py` (39 lines)
- Not used during normal generation — invoked only by `benchmark`, `profile`, `info` subcommands

**`tests/`:**
- Purpose: Full pytest test suite with mocking of diffusers and hardware-specific APIs
- Contains: One test file per source module, plus shared `conftest.py`
- Key files: `test_neural_engine.py` (544 lines), `test_profiler.py` (562 lines) — largest due to fixture complexity
- `conftest.py`: Defines `requires_mps` marker, shared pipeline/config fixtures

**`docs/`:**
- Purpose: Delivery documentation
- Contains: `DEVOPS-HANDOFF.md` — environment requirements, deployment notes

## Naming Conventions

**Files:**
- Source modules: `snake_case.py` (e.g., `neural_engine.py`, `config.py`)
- Test files: `test_{module_name}.py` mirroring source layout

**Directories:**
- Lowercase, no hyphens (e.g., `optimizers/`, `utils/`, `tests/`)

**Classes:**
- `PascalCase` — `FluxKreaPipeline`, `FluxWebApp`, `MetalOptimizer`, `NeuralEngineOptimizer`, `ThermalManager`, `FluxProfiler`

**Functions:**
- `snake_case` — `get_config()`, `run_benchmark()`, `get_system_info()`, `create_ui()`

**Enums:**
- `PascalCase` class, `UPPER_CASE` members — `OptimizationLevel.MAXIMUM`, `ThermalState.CRITICAL`

**Config env vars:**
- `FLUX_` prefix + `SECTION_FIELD` in `UPPER_CASE` — e.g., `FLUX_GENERATION_WIDTH`, `FLUX_DEVICE_MPS_MEMORY_FRACTION`

## Where to Add New Code

**New CLI subcommand:**
- Add handler function `cmd_{name}(config, args)` in `flux-krea/main.py`
- Add `subparsers.add_parser(...)` in `main()` and register in `commands` dict
- Import pipeline/util lazily inside the handler (pattern already established)

**New optimization strategy:**
- Add new class to `flux-krea/optimizers/` following `MetalOptimizer` pattern
- Register in `flux-krea/optimizers/__init__.py` `get_optimizer()` factory
- Add activation branch in `pipeline.py` `_apply_maximum_optimizations()` with `try/except ImportError`

**New config section:**
- Add `@dataclass` in `flux-krea/config.py` (e.g., `NewFeatureConfig`)
- Add field to `FluxConfig` with `field(default_factory=NewFeatureConfig)`
- Add section to `_apply_yaml()`, `_apply_env_vars()`, `_apply_overrides()` section maps
- Add corresponding block to `flux-krea/config.yaml`
- Add validation rules to `FluxConfig.validate()`

**New utility / diagnostic:**
- Add module to `flux-krea/utils/` (e.g., `utils/memory_tracker.py`)
- Import lazily in the relevant `main.py` subcommand handler
- Add test file `tests/test_memory_tracker.py`

**New generation parameter:**
- Add to `GenerationConfig` dataclass in `config.py`
- Add to `get_effective_generation_params()` return dict
- Pass through in `pipeline.generate()` to `self.pipeline(...)` call
- Expose as Gradio control in `app.py` `create_ui()`

## Special Directories

**`outputs/` and `web_outputs/`:**
- Purpose: Generated PNG images from CLI and web respectively
- Pattern controlled by `config.output.filename_pattern` (default: `flux_{timestamp}_{prompt_slug}.png`)
- Generated: Yes (at runtime)
- Committed: No (gitignored)

**`neural_engine_cache/`:**
- Purpose: Persisted CoreML `.mlpackage` files from `NeuralEngineOptimizer.compile_vae_decoder()`
- Generated: Yes (at runtime, if CoreML conversion succeeds)
- Committed: No (gitignored)
- Location override: Pass `cache_dir` to `NeuralEngineOptimizer(config, cache_dir=...)`

**`models/`:**
- Purpose: Local HuggingFace model cache (alternative to `~/.cache/huggingface/hub`)
- Generated: Yes (if model downloaded locally)
- Committed: No (gitignored)

**`.github/workflows/`:**
- Purpose: CI pipeline definitions
- Contains: `ci.yml` — pytest (excluding `requires_mps`), ruff, mypy
- Committed: Yes
