# Architecture

> Generated by gsd-codebase-mapper (arch focus) on 2026-04-13

## Pattern Overview

**Overall:** Layered pipeline application with strategy-based optimization

**Key Characteristics:**
- Single unified pipeline (`FluxKreaPipeline`) replaces ~40 prior file variants
- Three-tier optimization strategy (NONE / STANDARD / MAXIMUM) with automatic fallback chain
- Config-first design: all tunables flow from `FluxConfig` dataclass through layered loading
- Optimizers and utils are optional plug-ins; core inference path has no hard dependency on them
- Concurrency handled at the web layer (threading.Lock + SIGALRM timeout); pipeline itself is single-threaded

---

## Layers

**CLI / Web Layer:**
- Purpose: Accept user input, construct config, dispatch to pipeline or utility functions
- Location: `flux-krea/main.py`, `flux-krea/app.py`
- Contains: argparse subcommand routing, Gradio UI components, timeout/concurrency logic
- Depends on: `config.py`, `pipeline.py`, `utils/benchmark.py`, `utils/monitor.py`
- Used by: End users (CLI) and browser clients (Gradio)

**Configuration Layer:**
- Purpose: Single source of truth for all runtime parameters; enforces type safety and validation
- Location: `flux-krea/config.py`, `flux-krea/config.yaml`
- Contains: `FluxConfig` dataclass (7 nested sub-configs), `OptimizationLevel` enum, `ThermalMode` enum, layered load functions
- Depends on: `yaml`, `os` (stdlib only — no project dependencies)
- Used by: Every other module

**Pipeline Layer:**
- Purpose: Load, run, and unload the diffusers `FluxPipeline`; apply optimization levels; manage device memory
- Location: `flux-krea/pipeline.py`
- Contains: `FluxKreaPipeline` class with `load()`, `generate()`, `save_image()`, `unload()`
- Depends on: `config.py`, `diffusers.FluxPipeline` (lazy import at load time), `optimizers/metal.py`, `optimizers/thermal.py` (both lazy, optional)
- Used by: `main.py`, `app.py`, `utils/benchmark.py`, `utils/profiler.py`

**Optimizer Layer:**
- Purpose: Apply hardware-specific optimizations on top of a loaded pipeline
- Location: `flux-krea/optimizers/`
- Contains: `MetalOptimizer`, `NeuralEngineOptimizer`, `ThermalManager`, factory `get_optimizer()`
- Depends on: `config.py`, `torch` (Metal/Thermal), `coremltools` (Neural Engine, optional)
- Used by: `pipeline.py` (`_apply_maximum_optimizations`) only

**Utilities Layer:**
- Purpose: Diagnostic, benchmarking, and profiling tools; no production inference role
- Location: `flux-krea/utils/`
- Contains: `run_benchmark()`, `get_system_info()`, `FluxProfiler`
- Depends on: `config.py`, `pipeline.py`, `torch`, `psutil` (optional)
- Used by: `main.py` (`benchmark`, `profile`, `info` subcommands)

## Data Flow

**CLI generate path:**

1. `main.py`: Parse args → call `get_config(**overrides)` (config.py)
2. `config.py`: Load `config.yaml` → apply `FLUX_*` env vars → apply CLI overrides → validate
3. `main.py` → `FluxKreaPipeline(config)` (pipeline.py)
4. `pipeline.load()`: Configure MPS env → detect device → call `FluxPipeline.from_pretrained()` → apply optimization level
5. If MAXIMUM: `MetalOptimizer.optimize_pipeline()` + `ThermalManager.start_monitoring()`
6. `pipeline.generate()`: Resolve params via `config.get_effective_generation_params()` → consult `ThermalManager` for step scaling → run diffusers inference under `torch.inference_mode()` → return `(PIL.Image, metrics_dict)`
7. `pipeline.save_image()`: Write PNG to `config.output.directory` with pattern-based filename
8. `pipeline.unload()`: Stop thermal monitor → delete pipeline → clear MPS cache

**Web generate path:**

1. `main.py` → `app.create_ui(config)` (app.py)
2. `FluxWebApp.__init__()` → owns `FluxKreaPipeline` instance
3. On UI load: `start_loading()` spawns background thread → calls `pipeline.load()`
4. On generate click: acquire `threading.Lock` → arm `SIGALRM` timeout → call `pipeline.generate()` → release lock → return `(image, info_string, debug_log)`

**Optimization fallback chain:**

```
pipeline.load()
  -> _load_at_level(MAXIMUM)
       fail -> _load_at_level(STANDARD)
                  fail -> _load_at_level(NONE)
                               fail -> raise
```

**Config loading priority (highest to lowest):**

```
CLI overrides / _apply_overrides()
  > FLUX_* environment variables / _apply_env_vars()
  > config.yaml / _apply_yaml()
  > FluxConfig dataclass defaults
```

**State management:**
- No global mutable state. `FluxKreaPipeline` holds all pipeline state as instance attributes (`self.pipeline`, `self.is_loaded`, `self._metal_optimizer`, `self._thermal_manager`)
- `FluxWebApp` holds concurrency primitives (`threading.Lock`, `threading.Event`) and session gallery
- `ThermalManager` maintains `_current_metrics` and `_current_profile` updated by background thread

## Key Abstractions

**FluxConfig:**
- Purpose: Central configuration object passed to every component; eliminates per-component config duplication
- File: `flux-krea/config.py`
- Pattern: Python dataclass with nested sub-configs; validated after construction via `validate()`
- Key method: `get_effective_generation_params()` merges safety mode overrides at call time

**OptimizationLevel enum (NONE / STANDARD / MAXIMUM):**
- Purpose: Determines which subset of hardware-specific optimizations are activated
- File: `flux-krea/config.py`
- Pattern: Strategy selection — `pipeline._load_at_level()` switches on this enum
- STANDARD applies: MPS device placement, attention slicing, VAE tiling/slicing, `AttnProcessor2_0`
- MAXIMUM adds: Metal VAE autocast (`MetalOptimizer`), background temperature monitoring (`ThermalManager`), optional CoreML VAE conversion (`NeuralEngineOptimizer`, not called from pipeline directly — available via factory)

**FluxKreaPipeline:**
- Purpose: Single stable interface for all generation scenarios, hiding optimization complexity
- File: `flux-krea/pipeline.py`
- Pattern: Facade — wraps diffusers `FluxPipeline`, optimizer objects, and memory management behind a clean `load/generate/save/unload` API

**ThermalManager:**
- Purpose: React to system temperature by scaling inference steps to prevent thermal throttling
- File: `flux-krea/optimizers/thermal.py`
- Pattern: Background thread + polling; emits `PerformanceProfile` objects; pipeline queries `get_current_profile()` before each generate call

**NeuralEngineOptimizer:**
- Purpose: Attempt CoreML/ANE conversion of pipeline sub-components (VAE decoder only is realistic; T5-XXL and transformer are too large)
- File: `flux-krea/optimizers/neural_engine.py`
- Pattern: Optional accelerator with cache (`./neural_engine_cache/`); lazy `coremltools` import; always returns pipeline in usable state regardless of conversion success

## Entry Points

**CLI:**
- Location: `flux-krea/main.py` → `main()` function
- Triggers: `python main.py {generate|web|benchmark|profile|info}` or `./launch.sh`
- Responsibilities: Parse args, build config, route to subcommand handler; all handlers import lazily to avoid loading heavy deps on `info`/`benchmark` invocations

**Web UI (standalone):**
- Location: `flux-krea/app.py` → `main()` function (or `create_ui()` called from `main.py`)
- Triggers: `python app.py` (direct) or `python main.py web`
- Responsibilities: Construct `FluxWebApp`, build Gradio blocks, start background pipeline load, serve

**Shell launcher:**
- Location: `flux-krea/launch.sh`
- Triggers: `./launch.sh {subcommand}`
- Responsibilities: Source `.env` file, delegate to `python main.py`

## Error Handling

**Strategy:** Defensive — every optimization step is wrapped in try/except; failures downgrade rather than crash.

**Patterns:**
- Optimization fallback: MAXIMUM → STANDARD → NONE with `logger.warning` at each step
- MPS watermark RuntimeError: explicitly caught and silenced in `_cleanup_memory()` and `MetalOptimizer._safe_empty_cache()`
- Web timeout: `SIGALRM` on Unix; `TimeoutError` caught and returned as user-visible message with `_format_error()` which maps error patterns to actionable solutions (gated repo, auth, OOM, timeout)
- CoreML conversion failures: logged and silently bypassed; pipeline continues on MPS
- Missing optional dependencies (`psutil`, `coremltools`): `ImportError` caught; functions return `None` or empty dict rather than raising

## Cross-Cutting Concerns

**Logging:** Python `logging` module throughout. Logger named per module (`logger = logging.getLogger(__name__)`). Level set by `--verbose` flag in `main.py`. Web layer additionally maintains an in-memory `deque(maxlen=50)` debug log surfaced in the Gradio UI.

**Validation:** `FluxConfig.validate()` runs after every config load. Checks: resolution multiples of 64, positive steps/guidance, watermark ratio ordering, memory fraction bounds, thermal threshold ordering, optimization level enum membership.

**Authentication:** HuggingFace token read only from env (`HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN`) via `get_hf_token()` in `config.py`. Never hardcoded or written to disk.

**Memory management:** `_cleanup_memory()` called before and after every generation. MPS cache cleared via `torch.mps.empty_cache()`. `pipeline.unload()` deletes the pipeline object and calls `gc.collect()`.

**Device detection:** `_detect_device()` in `pipeline.py` follows `config.device.preferred` (mps > cuda > cpu) with availability checks. MPS environment variables set via `apply_mps_environment()` in `config.py` before any torch import.

**Thread safety:** Web layer uses `threading.Lock` (non-blocking acquire rejects concurrent requests with message). `ThermalManager` background thread writes to `_current_metrics` and `_current_profile`; pipeline reads these without locking (acceptable — writes are atomic Python attribute assignments).

```
  ├── config.py (always)
  ├── pipeline.py (generate, profile subcommands)
  ├── app.py (web subcommand)
  └── utils/
      ├── benchmark.py (benchmark subcommand)
      ├── monitor.py (info subcommand)
      └── profiler.py (profile subcommand)

app.py
  ├── config.py
  └── pipeline.py

pipeline.py
  ├── config.py
  ├── diffusers.FluxPipeline (lazy, at load time)
  ├── optimizers/metal.py (lazy, MAXIMUM only)
  └── optimizers/thermal.py (lazy, MAXIMUM only)

optimizers/__init__.py
  ├── config.py
  ├── optimizers/metal.py (MAXIMUM only)
  ├── optimizers/neural_engine.py (MAXIMUM only)

optimizers/metal.py      -> config.py, torch
optimizers/neural_engine.py -> config.py, coremltools (optional), torch (lazy)
optimizers/thermal.py    -> config.py, psutil (optional), subprocess

utils/benchmark.py       -> config.py, pipeline.py
utils/monitor.py         -> torch, psutil (optional)
utils/profiler.py        -> config.py, pipeline.py (passed as arg, not imported)

config.py                -> yaml, os (no project imports)
```
